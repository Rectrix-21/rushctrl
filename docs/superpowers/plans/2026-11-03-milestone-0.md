# Milestone 0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A locally runnable, tested Next.js/API/PostgreSQL foundation with the approved blue glass dashboard shell.

**Architecture:** One Next.js App Router frontend, one ASP.NET Core modular monolith, PostgreSQL through EF Core. Same-origin proxying covers API and health paths. Public operational endpoints contain no tenant data; authorization defaults to authenticated access.

**Tech Stack:** Node 24, Next.js 16.4.4, React 19.3.1, TypeScript, .NET SDK 10.0.403, EF Core 10.0.14, Npgsql 10.0.3, PostgreSQL 18, xUnit, Playwright, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-11-03-milestone-0-design.md` (owner approved in chat).

## Global Constraints

- Standalone app in `D:/Coding/rushctrl`; no external deployment, accounts, paid resources, or Git remote.
- No real employee data or committed credentials; all staffing display content is labelled synthetic.
- No production identity workflow or staffing writes until Milestone 1.
- No added AI branding, boilerplate attribution comments, or co-author trailers.
- Project-local SDK and optional PostgreSQL only; do not install Docker Desktop or change WSL/system features.
- Explain each increment and report actual verification limits.

## Review Focus

- Reachable but unmigrated PostgreSQL must report not ready: Task 2 database integration test.
- Failed API/database requests must not look healthy: Task 3 status logic and browser smoke tests.
- Unauthenticated protected endpoints must return 401, never redirect: Task 1 API test.
- Mobile schedule overflow must stay inside the timeline: Task 3 browser check, pending browser authority if unavailable.
- Missing secrets must fail local setup clearly, not fall back to committed defaults: Task 4 configuration validation.

## File responsibilities

`src/RushCtrl.Api/Program.cs` wires the API; `Modules/System` owns health and service metadata; `Infrastructure/RushCtrlDbContext.cs` owns relational mapping; `Infrastructure/Migrations` holds generated schema changes; `Modules/Organizations` contains the two initial entities. Tests live under `tests/RushCtrl.Api.Tests`.

`apps/web/src/app` owns routing/layout; `components/dashboard` owns sample dashboard components; `components/system-status.tsx` owns real operational state; `lib/api.ts` owns typed requests; `tests` contains status and Playwright smoke tests. `compose.yaml`, Dockerfiles and scripts own local orchestration. README, ADRs, API reference and learning log describe the implemented behavior.
