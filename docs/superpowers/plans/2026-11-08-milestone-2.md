**Goal:** Explain and atomically resolve coverage shortages, demonstrate a safely resettable Friday Rush, and refresh another session through SignalR.

**Architecture:** Extend the current modular monolith and same-origin Next.js UI. One organization transaction boundary owns writes, audit and post-commit notification. Simulation uses real services in an owner-only synthetic organization with generation guards.

**Tech Stack:** Existing .NET 10/EF Core/Npgsql, PostgreSQL 18, Next.js/React/TypeScript/Zod, xUnit and Playwright. Add the supported official SignalR JavaScript client after version verification.

## Global constraints

- Keep the open VS Code folder and `milestone-2` branch; small local commits, no remote push/merge/deployment by the agent.
- Preserve synthetic-only local scope, blue glass design, credentials, normal workspace edits and tenant/CSRF/identity guards.
- No invented measurements, auto-assignment, real employee data, authorship branding or artificial co-author trailers.
- All scheduling intervals remain half-open; every touched Monday week uses the target location's stored time zone and existing cap.
- Explain each increment in beginner language with reproducible exercises and observed test results.

## Review focus

- A reset during an open form must not write into a new generation: Task 3 stale-generation/competing-write tests and Task 4 captured form context.
- A changed shared sign-in cookie must not silently rebind a live connection or a form: Task 4 identity/reconnect regressions.
- Committed writes must remain successful if notification fails, while failed writes must create neither audit nor invalidation: Tasks 1 and 4.
- Resolved request history must not block new requests/direct assignments or expose another employee's history: Task 1 tests and Task 4 UI filtering.
- Scenario Apply after manual edits or expiry must refuse rather than invent a changed deterministic scenario: Task 3 tests.
